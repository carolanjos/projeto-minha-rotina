Exercício de recursão: filtrar tarefas por pendências em qualquer nível.

    Ver a lógica por trás do filtro "Com pendências"

    Cada tarefa carrega um array subtasks (vazio quando é uma folha). O filtro usa duas peças:

    function hasPendingDeep(task) {
  if (!task.done) return true;
  return task.subtasks.some(hasPendingDeep);
}

function makeFilter(kind) {
  if (kind === 'all') return () => true;
  if (kind === 'pending') return t => !t.done;
  if (kind === 'done') return t => t.done;
  if (kind === 'nested-pending') return t => hasPendingDeep(t);
}

    O caso base não é um if explícito: quando subtasks está vazio, .some() percorre zero itens e retorna false sozinho — é o array vazio que resolve a recursão, não uma linha extra de código.

    Repare em dois comportamentos que só aparecem testando com tarefas reais:

    • "Ler artigo sobre closures" está incompleta e sua única subtarefa já foi concluída — mesmo assim aparece em "Com pendências", porque !task.done já é true na própria tarefa, antes mesmo de olhar para as subtarefas.
    • "Preparar apresentação de sexta" está marcada como concluída, mas tem uma subtarefa pendente — ela aparece em "Com pendências" (a recursão desceu até achar a pendência), embora também apareça em "Concluídas" (o filtro done olha só para o topo). É um sinal de que "pendência em qualquer nível" e "tarefa concluída" são perguntas independentes.
